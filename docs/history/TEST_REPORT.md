## Portal modal close regression

The user-reported issue was reproduced conceptually from the old implementation: the portal CSP allows `script-src 'self'` while legacy modal close buttons depended on inline `onclick`, which browsers correctly block.

v2.0.0 removes that dependency and uses one delegated modal controller. The exact frontend JavaScript served by the final packaged binary was loaded in a real Chromium renderer and tested with browser DOM events.

### Browser-lab note

The container's system Chromium is currently subject to an externally managed `URLBlocklist: ["*"]` policy, so direct Chromium navigation to the local HTTP test server is blocked by the host browser policy rather than by Flow Collector. The backend/API runtime was therefore tested against the real running process, while the exact packaged HTML/JavaScript was tested in the Chromium renderer using `Page.setDocumentContent` and browser DOM events. No system browser policy was disabled or bypassed.

## Administration safety boundaries

- database/web/OIDC/LDAP/cluster-class changes are classified as critical and require an operator reason
- settings are validated and diffed before apply
- secrets are write-only/redacted in portal/API views
- restart-required changes are staged rather than silently represented as active
- environment variables remain highest-precedence overrides
- metadata restore is verified and scheduled for controlled restart before listeners reopen
- destructive storage operations remain audited and explicit
- CLI disaster-recovery paths remain available even when the portal is unavailable

## External-lab boundaries

- No live multi-host ClickHouse Keeper failover/recovery lab was available; installer/schema contract tests are not represented as a real Keeper failover test.
- No external enterprise LDAP/AD or third-party OIDC provider was available in this final container run; deterministic protocol/mapping regressions remain covered by the Go suite.
- The system Chromium direct-navigation limitation described above is caused by a host-managed URL block policy. Exact packaged frontend modal behavior was nevertheless validated in the Chromium rendering engine.
